No `LICENSE` file or package-level licence declaration has been added. `private: true` prevents accidental npm publication; it does not choose a licence or control GitHub visibility.

**Recommendation for consideration: MIT.** For a CV/source demonstration, MIT allows broad reuse with a short notice requirement. The owner must confirm authorship and rights to the retained code, favicon and styling before authorizing it. The [MIT licence overview](https://choosealicense.com/licenses/mit/) describes its permissions and notice requirements.

**Alternative: Apache-2.0.** Consider it if an express contributor patent grant and the associated notice rules better fit the intended reuse. See the [official Apache-2.0 text](https://www.apache.org/licenses/LICENSE-2.0). Choosing it requires reviewing those additional terms, not merely changing a label.

An owner decision should specify the licence and copyright holder/year, confirm any employer/client or third-party authorship restrictions, and approve the publication scope. Then add the complete chosen licence text and package declaration, refresh the release archive and notices, and obtain a separate instruction before pushing or publishing.
